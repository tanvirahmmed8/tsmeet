## Documentation conventions

These rules keep the docs trustworthy. Please follow them in pull requests.

1. **Document what the code does, not what it should do.** If a feature is
   planned, put it in an issue, not in a reference document.
2. **Separate measured from configured.** `MAX_PARTICIPANTS=50` is a ceiling;
   20 is the tested figure. Always say which one you mean.
3. **Mark optional things optional.** Recording and observability are off by
   default; a reader must not assume they are running.
4. **Never invent an endpoint or event.** [../API.md](../API.md) is generated by
   reading `server/routes/` and `server/index.ts`. If you add or remove one,
   update that file in the same pull request.
5. **Never paste real secrets** — not in docs, examples, issues, or logs.
6. **Keep the audience split.** User-facing docs avoid ports, env vars, and
   service names; developer and operator docs are free to use them.
